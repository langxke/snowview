# 雪象 (SnowView) 项目需求文档

## 1. 项目概述

### 1.1 项目基本信息
- **项目名称**：雪象 (SnowView)
- **项目类型**：桌面端应用程序
- **开发平台**：Flutter
- **目标平台**：Windows、macOS、Linux
- **开发模式**：个人项目
- **架构模式**：单体应用架构

### 1.2 项目定位
雪象是一款基于AI辅助的智能日程规划和专注工具，旨在帮助用户高效管理学习任务、提升专注力，通过智能算法优化时间分配，实现个人目标的高效达成。

### 1.3 目标用户
- **主要用户**：学生、职场人士、自由职业者
- **使用场景**：学习新技能、项目管理、个人效率提升
- **用户特征**：注重效率、有明确学习目标、需要时间管理工具

## 2. 核心功能需求

### 2.1 AI任务生成模块
- **功能描述**：基于用户输入的学习目标，自动生成具体的任务列表
- **输入方式**：文本输入、语音输入（后期扩展）
- **AI服务**：OpenAI GPT-3.5/4.0 API
- **输出内容**：
  - 任务标题和详细描述
  - 任务优先级分类
  - 预估完成时间
  - 任务依赖关系
  - 学习资源推荐

### 2.2 智能日程规划模块
- **功能描述**：将生成的任务智能分配到用户的时间表中
- **规划算法**：
  - 基于用户时间偏好（工作日/周末、工作时间段）
  - 任务优先级排序
  - 任务依赖关系考虑
  - 用户专注力曲线优化
- **时间管理**：
  - 支持自定义工作时间
  - 休息时间自动安排
  - 任务缓冲时间预留
- **动态调整**：
  - 任务延期自动重排
  - 临时任务插入处理
  - 计划变更智能提醒

### 2.3 专注工具模块
- **番茄钟功能**：
  - 标准25分钟工作+5分钟休息
  - 自定义时间设置
  - 长休息时间（每4个番茄钟后15-30分钟）
  - 专注模式（屏蔽干扰）
- **专注时间记录**：
  - 每日专注时间统计
  - 任务专注时长记录
  - 专注效率分析
- **环境音效**：
  - 白噪音播放
  - 自然声音（雨声、海浪等）
  - 背景音乐集成

### 2.4 任务管理模块
- **基础功能**：
  - 任务创建、编辑、删除
  - 任务状态跟踪（待办、进行中、已完成、已取消）
  - 任务分类标签
  - 任务搜索和筛选
- **高级功能**：
  - 任务模板保存
  - 任务复制和移动
  - 批量操作
  - 任务历史记录

### 2.5 数据管理模块
- **本地存储**：
  - Hive NoSQL数据库存储
  - 数据自动序列化/反序列化
  - 自动备份机制
- **数据导出**：
  - JSON格式导出
  - CSV格式导出
  - 任务报告生成
- **数据同步**（预留扩展）：
  - 云端同步接口预留
  - 多设备数据同步
  - 数据冲突解决机制

- **隐私保护**：用户数据不上传第三方（除AI服务外）

### 3.4 可用性需求

- **操作便捷**：支持键盘快捷键

### 4.2 项目结构详解

#### 4.2.1 整体架构说明
本项目采用**Clean Architecture（清洁架构）**设计模式，参考滴答清单、微软Todo等成熟产品的架构设计，将代码分为四个层次：

1. **表现层（Presentation Layer）**：负责UI展示和用户交互
2. **业务逻辑层（Domain Layer）**：包含核心业务规则和用例
3. **数据层（Data Layer）**：负责数据存储和外部API调用
4. **服务层（Services Layer）**：提供跨模块的通用服务

#### 4.2.3 架构层次说明

**1. 仓库接口（Repository Interface）**
- **作用**：定义数据操作的抽象接口，实现依赖倒置原则
- **示例**：`TaskRepositoryInterface`、`ScheduleRepositoryInterface`、`FocusRepositoryInterface` 分别定义任务、日程与专注数据的读写契约
- **好处**：业务逻辑层不依赖具体的数据实现，便于测试和切换数据源

**2. 用例（Use Case）**
- **作用**：封装具体的业务操作流程，每个用例代表一个完整的业务场景
- **示例**：`CreateTaskUseCase` 包含创建任务的完整流程；`StartFocusSessionUseCase` 依赖 `FocusRepositoryInterface` 管理专注会话；`GenerateScheduleUseCase` 产生日程集合
- **好处**：业务逻辑清晰，易于测试和维护

**3. 服务层（Services Layer）**
- **作用**：提供跨模块的通用服务，处理复杂的业务逻辑
- **示例**：`ScheduleService` 包含日程规划的复杂算法，`AIService` 封装OpenAI API调用
- **好处**：复用性强，便于统一管理和优化

### 4.3 数据存储设计详解

#### 4.3.1 数据存储设计原则
参考滴答清单、微软Todo等成熟产品的数据模型设计，采用Hive NoSQL数据库设计，支持：
- **任务层次化**：支持主任务和子任务关联
- **时间管理**：精确的时间记录和统计
- **标签系统**：灵活的任务分类和标签
- **专注统计**：详细的效率分析数据

#### 4.3.2 Hive数据模型详细说明

#### 4.3.3 Hive数据存储设计特点

**1. 参考成熟产品设计**
- **滴答清单**：借鉴了任务层次化、标签系统、时间管理等特点
- **微软Todo**：参考了优先级系统、状态管理、简洁的数据结构
- **Notion**：学习了灵活的关联关系和扩展性设计

**2. Hive技术优势**
- **高性能**：直接存储Dart对象，读写速度极快
- **类型安全**：强类型模型，编译时检查数据结构
- **自动序列化**：无需手动编写JSON转换代码
- **跨平台**：支持所有Flutter平台的本地存储

**3. 支持核心功能**
- **AI任务生成**：Task模型支持AI生成的任务数据
- **智能日程规划**：Schedule模型支持复杂的时间安排
- **专注工具**：FocusSession模型详细记录专注数据
- **效率分析**：FocusStats模型提供统计数据

**4. 数据关联设计**
- **标签系统**：通过tagIds列表实现任务与标签的多对多关系
- **子任务**：parentTaskId支持任务层次化结构
- **时间统计**：详细的时长记录支持效率分析
- **状态管理**：完整的状态流转支持

**5. 数据完整性保障**
- **UUID标识**：使用UUID确保数据的唯一性
- **类型约束**：Hive类型注解确保数据结构正确
- **默认值**：构造函数提供合理的默认设置
- **时间戳**：自动记录创建和更新时间

**6. Box分组策略**
- **功能分离**：不同功能模块使用独立的Box存储
