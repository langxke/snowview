# 任务-日历联动完整落实方案

## 核心设计思路

**底层实现**：工作会话（WorkSession）作为任务与日历的桥梁  
**界面展示**：日历中显示真实的任务名称，而非"会话x"  
**数据关联**：一个任务可以有多个工作会话，一个会话可以关联到整个任务或某个子步骤

  }

## 设计说明：为什么去除"开始"按钮

### 原始设计的问题

在最初的设计中，工作会话包含了 `ongoing`（进行中）状态和相关的实时追踪字段：
- `actualStartTime` - 实际开始时间
- `actualEndTime` - 实际结束时间  
- `actualDuration` - 实际时长
- `startSession()` - 开始会话方法
- `completeSession()` - 完成会话方法

这导致了以下问题：

**1. 功能不完整**
- 有"开始"按钮但没有"暂停"、"停止"按钮
- 无法处理中断和恢复
- 没有实时计时显示
- 用户点击"开始"后不知道下一步做什么

**2. 功能重叠**
- 工作会话试图做时间追踪，但很简陋
- 专注功能（番茄钟）会做完整的时间追踪
- 两个功能重叠，但工作会话的实现很弱

**3. 定位模糊**
- 工作会话到底是规划工具还是追踪工具？
- 用户什么时候用"开始"，什么时候用专注功能？

### 优化后的设计

**清晰的功能分工**：

| 功能 | 工作会话 | 专注功能（番茄钟） |
|------|---------|------------------|
| **定位** | 时间规划工具 | 时间追踪工具 |
| **场景** | "我计划明天下午2点做这个任务" | "我现在开始做任务，计时25分钟" |
| **关键功能** | 创建、编辑、删除时间安排 | 开始、暂停、继续、完成计时 |
| **数据** | 计划时间、关联任务/子步骤 | 实际开始/结束时间、实际时长 |
| **UI** | 任务详情、日历视图 | 独立的专注页面/浮窗 |

**工作流程**：
1. 用户在任务详情创建工作会话（规划）
2. 日历中显示这些会话
3. 到了时间，用户点击"开始专注"
4. 进入专注功能（番茄钟）进行实际工作
5. 专注完成后，工作会话自动标记为"已完成"
6. 实际时长从专注会话获取

**优势**：
- ✅ 职责清晰：规划归规划，执行归执行
- ✅ 避免重复：不重复实现时间追踪功能
- ✅ 数据准确：实际时长由专业的追踪工具记录
- ✅ 用户友好：操作路径清晰，不会困惑
