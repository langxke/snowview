## 数据流示例

### 场景：用户在多个会话中同时发送消息

```
用户操作：
1. 在会话 A 发送消息 "创建任务：学习 Flutter"
2. 立即切换到会话 B
3. 在会话 B 发送消息 "今天有什么安排？"

数据流：

Step 1: 发送消息到会话 A
┌────────┐
│  User  │
└───┬────┘
    │ sendMessage("创建任务：学习 Flutter")
    ▼
┌─────────────┐
│ AIProvider  │ ─── 委托给 ──→ AISession A
└─────────────┘
                          │
                          │ 开始流式生成
                          ▼
                    AI 返回工具调用
                          │
                          │ 委托给
                          ▼
                 AIToolCallOrchestrator
                          │
                          │ 执行工具
                          ▼
                    创建任务 "学习 Flutter"
                          │
                          │ 获取最终回复
                          ▼
                    "已为您创建任务..."

Step 2: 切换到会话 B（会话 A 继续在后台执行）
┌────────┐
│  User  │ switchSession(sessionB.id)
└───┬────┘
    ▼
┌─────────────┐
│ AIProvider  │ ─── currentSessionId = sessionB.id
└─────────────┘     ⚠️ 注意：不停止会话 A 的生成
                    ✅ 会话 A 在后台继续执行工具调用

Step 3: 发送消息到会话 B（会话 A 仍在后台执行）
┌────────┐
│  User  │ sendMessage("今天有什么安排？")
└───┬────┘
    ▼
┌─────────────┐
│ AIProvider  │ ─── 检查并发限制（2/3）✅ 允许
└─────────────┘
                │
                │ 委托给
                ▼
         AISession B
                │
                │ 开始流式生成
                ▼
         AI 返回工具调用
                │
                │ 委托给
                ▼
    AIToolCallOrchestrator
                │
                │ 执行工具
                ▼
         查询今天的日程
                │
                │ 获取最终回复
                ▼
         "您今天有 3 个安排..."

同时，会话 A 在后台也完成了：
  - 工具执行完成
  - 最终回复生成完成
  - 消息保存到数据库
  - isThinking = false
  - 通知 UI 更新（但不显示，因为不是当前会话）
```

## 状态管理

### 会话状态

每个 `AISession` 独立维护：
```dart
class AISession {
  List<ChatMessageHive> messages = [];  // 该会话的消息
  bool isThinking = false;              // 是否正在生成
  String? errorMessage = null;          // 错误信息
  StreamSubscription? _streamSubscription;  // Stream 订阅
  bool _shouldStop = false;             // 停止标志
}
```

### 全局状态

`AIProvider` 维护：
```dart
class AIProvider {
  Map<String, AISession> _sessions = {};  // 所有会话实例
  String? _currentSessionId;              // 当前显示的会话
  String _currentMode = 'action';         // AI 工作模式
  int _maxConcurrentSessions = 3;         // 最大并发数
}
```

## 并发控制

### 并发限制策略

```
允许的并发数：3

场景 1：正常情况
┌──────────┐  ┌──────────┐  ┌──────────┐
│ Session A│  │ Session B│  │ Session C│
│ 生成中... │  │ 生成中... │  │ 生成中... │
└──────────┘  └──────────┘  └──────────┘
     ✅            ✅            ✅
   (1/3)         (2/3)         (3/3)

场景 2：达到限制
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ Session A│  │ Session B│  │ Session C│  │ Session D│
│ 生成中... │  │ 生成中... │  │ 生成中... │  │ 等待中... │
└──────────┘  └──────────┘  └──────────┘  └──────────┘
     ✅            ✅            ✅            ❌
   (1/3)         (2/3)         (3/3)      已达上限

提示用户：
"🚦 同时生成的会话过多（3/3）
请等待其他会话完成，或停止其他会话的生成。"
```

### 并发控制代码

```dart
Future<void> sendMessage(String content) async {
  // 检查并发限制
  if (generatingSessionsCount >= _maxConcurrentSessions) {
    // 提示用户
    return;
  }
  
  // 继续处理消息
  final session = _getOrCreateSession(_currentSessionId!);
  await session.sendMessage(content);
}
```

## 切换策略

### 重构前（问题）

```dart
Future<void> switchSession(String sessionId) async {
  if (_isThinking) {
    await stopGenerating();  // ❌ 强制停止
  }
  
  _currentSessionId = sessionId;
  await _loadHistory();
}
```

**问题**：
- 切换会话会丢失正在生成的内容
- 用户必须等待生成完成
- 体验不佳

### 重构后（解决）

```dart
Future<void> switchSession(String sessionId) async {
  if (_currentSessionId == sessionId) return;
  
  print('[AI Provider] 📱 切换会话: $_currentSessionId -> $sessionId');
  
  // ✅ 不停止生成！让后台继续运行
  _currentSessionId = sessionId;
  _getOrCreateSession(sessionId);  // 确保会话实例存在
  
  _safeNotifyListeners();  // 只通知 UI 更新
}
```

**优势**：
- ✅ 无缝切换，不丢失内容
- ✅ 后台会话继续工作
- ✅ 可以随时切换

## 工具调用流程

### 工具调用处理流程

```
Step 1: AI 返回工具调用
┌──────────────┐
│  AISession   │ 收到 tool_calls
└──────┬───────┘
       │ 移除临时消息
       │ 委托给工具编排器
       ▼
┌─────────────────────────┐
│ AIToolCallOrchestrator  │
└─────────┬───────────────┘
          │
          ├─ Step 2: 生成执行计划消息
          │  "📋 执行计划（共 3 项操作）
          │   • 创建任务 × 1
          │   • 创建日程 × 2"
          │  → 通过回调添加到会话消息
          │
          ├─ Step 3: 顺序执行工具
          │  ├─ 执行工具 1
          │  │  → 生成 tool 消息（结果）
          │  ├─ 执行工具 2
          │  │  → 生成 tool 消息（结果）
          │  └─ 执行工具 3
          │     → 生成 tool 消息（结果）
          │
          ├─ Step 4: 获取最终回复
          │  ├─ 等待 2 秒（避免连接问题）
          │  ├─ 将所有消息发送给 AI
          │  └─ AI 生成最终总结
          │
          └─ Step 5: 返回结果
             ├─ 如果成功：返回最终回复消息
             ├─ 如果有新的工具调用：递归处理
             └─ 如果失败：返回错误消息
```

### 递归处理

工具调用可能触发新的工具调用（递归）：

```
深度 1: 用户消息 → AI 返回 [工具A]
  ↓ 执行工具A
  ↓ 获取最终回复
  
深度 2: AI 又返回 [工具B, 工具C]
  ↓ 执行工具B, 工具C
  ↓ 获取最终回复
  
深度 3: AI 返回纯文本回复
  ✓ 完成

递归深度限制：10 层
超过限制：自动停止，提示用户
```

## 错误处理

### 分层错误处理

```
┌─────────────────────────────────────────────────┐
│              AISession (会话层错误)              │
│  - 网络错误                                       │
│  - API 错误                                       │
│  - 上下文超长                                     │
│  → 显示友好错误消息                               │
│  → 添加错误消息到会话                             │
└─────────────────────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────┐
│       AIToolCallOrchestrator (工具调用错误)      │
│  - 工具执行失败                                   │
│  - 参数解析错误                                   │
│  - 递归深度超限                                   │
│  → 返回 ToolCallResult.error()                   │
│  → 会话添加降级消息                               │
└─────────────────────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────┐
│         AIToolExecutor (单个工具错误)            │
│  - 参数无效                                       │
│  - 执行异常                                       │
│  → 返回 {'success': false, 'error': '...'}      │
│  → 工具调用继续，不中断流程                       │
└─────────────────────────────────────────────────┘
```

## 总结

### 架构优势

1. **职责清晰**
   - AIProvider：调度
   - AISession：会话管理
   - AIToolCallOrchestrator：工具处理

2. **状态隔离**
   - 每个会话独立管理状态
   - 互不干扰

3. **并发支持**
   - 最多 3 个会话并发
   - 智能限流

4. **易于扩展**
   - 新增功能只需修改对应层
   - 不影响其他部分

### 代码质量

- ✅ 单一职责原则
- ✅ 开闭原则（对扩展开放，对修改关闭）
- ✅ 依赖倒置原则
- ✅ 接口隔离原则

### 用户体验

- ✅ 无缝切换
- ✅ 不丢失内容
- ✅ 清晰的状态指示
- ✅ 友好的错误提示
