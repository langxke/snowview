# 设计【是否完成】字段方案

根据您的需求，目前 `CalendarEventHive`（时间块）模型中**不存在**【是否完成】字段。现有的设计是依靠关联的 `Task`（任务）的状态来判断，但这种设计有缺陷：
1.  如果一个任务被分成了多个时间块（例如：早上1小时，下午1小时），当用户完成了早上的块，但任务本身还没做完时，我们无法标记早上的块为“已完成”。
2.  无法区分“用户确认过的过去时间块”和“因为没打开软件而错过的过去时间块”。

为了解决这个问题，并支持“下次打开软件时清除未完成的时间块”，我们需要在**时间块本身**记录状态。

## 方案设计

### 1. 字段添加
在 `CalendarEventHive` (数据层) 和 `CalendarEvent` (UI层) 中新增一个布尔字段：
*   **字段名**：`isCompleted`
*   **类型**：`bool`
*   **默认值**：`false`
*   **含义**：
    *   `true`: 用户已明确点击“已完成”，或该时间块对应的任务已完成。
    *   `false`: 用户尚未确认，或者用户明确点击了“未完成/下次再做”（但在那种情况下我们通常会直接删除块）。

### 2. 交互逻辑变更
*   **点击“已完成”**：
    *   更新 Task 状态为 Completed（如果需要）。
    *   **同时** 将当前 `CalendarEvent.isCompleted` 设为 `true`。
*   **点击“下次再做”**：
    *   直接**删除**该时间块（保持现有逻辑）。
*   **超时/未处理**：
    *   保持 `isCompleted = false`。

### 3. 清理逻辑优化 (Startup Cleanup)
应用启动时扫描所有 **已结束** 的时间块 (`end < now`)：
*   如果 `isCompleted == true`：保留（作为历史记录）。
*   如果 `isCompleted == false`：
    *   视为“过期未完成”。
    *   执行清理逻辑（删除块 + 重置关联任务状态）。

### 4. 实施步骤
1.  **修改模型**：
    *   更新 `CalendarEventHive` (添加 `@HiveField(7)`)。
    *   更新 `CalendarEvent` (添加 `isCompleted` 属性)。
    *   运行 `flutter packages pub run build_runner build` 重新生成适配器。
2.  **更新业务逻辑**：
    *   在 `ScheduleMonitor` 中，当用户点击“已完成”时，更新该 Event 的 `isCompleted` 为 `true`。
3.  **更新清理逻辑**：
    *   修改 `_cleanupPastTasks`，不再仅依赖 Task 状态，而是优先检查 Event 的 `isCompleted` 字段。
