# 解决方案：基于 DailyPlan 的全天候索引模型

您的想法非常棒。将时间块（Time Blocks）也纳入 `DailyPlan` 管理，确实能实现“单日数据的一站式获取”，将 `DailyPlan` 升级为**“每日视图的唯一真理源 (Single Source of Truth)”**。

## 1. 核心设计思路

采用 **“索引模式 (Index Model)”**：`DailyPlan` 作为一个**聚合索引**，存储当天所有相关实体的 ID，而具体的任务详情和时间块详情依然存储在各自的 Box 中（保证数据规范化，避免修改标题需要更新多处）。

### 数据模型设计 (`DailyPlanHive`)

```dart
@HiveType(typeId: 4)
class DailyPlanHive extends HiveObject {
  @HiveField(0)
  String dateKey; // 主键 "2023-10-27"

  // 1. 【今日任务 (全天)】：指向 ChecklistTask (原 allDay Events)
  @HiveField(1)
  List<String> allDayTaskIds; 

  // 2. 【今日待办】：指向 ChecklistTask
  @HiveField(2)
  List<String> todoTaskIds; 

  // 3. 【时间块 (日程)】：指向 CalendarEvent
  @HiveField(3)
  List<String> scheduledEventIds; 
}
```

---

## 2. 详细执行步骤 (Execution Steps)

我们将分四个阶段稳步推进重构。

### 第一阶段：基础设施建设 (Infrastructure)
1.  **创建模型文件**：
    *   在 `lib/data/models/` 下新建 `daily_plan_hive.dart`。
    *   定义上述 `DailyPlanHive` 类。
2.  **生成适配器**：
    *   运行 `build_runner` 生成 `.g.dart` 文件，注册 Hive Adapter。
3.  **创建 Repository**：
    *   新建 `DailyPlanRepository`，封装 Hive Box 的 CRUD 操作（如 `getPlanForDate`, `addTaskToToday`, `addEventToSchedule`）。

### 第二阶段：状态管理层 (Provider Layer)
1.  **创建 `DailyPlanProvider`**：
    *   **核心职责**：它是 UI 层和底层数据的桥梁。
    *   **方法设计**：
        *   `loadPlan(DateTime date)`: 加载指定日期的计划。
        *   `moveTaskToAllDay(String taskId)`: 将任务 ID 从 `todoTaskIds` 移入 `allDayTaskIds`。
        *   `addScheduledEvent(String eventId)`: 记录新生成的时间块。
2.  **联动机制**：
    *   当 `ScheduleProvider` 创建新 Event 时，同步调用 `DailyPlanProvider.addScheduledEvent`。

### 第三阶段：数据迁移与初始化 (Migration)
*由于是新老架构切换，需要一个“懒加载迁移”策略：*
*   当用户打开某一天（如“今天”）的视图时，检查是否存在 `DailyPlan`。
*   **如果不存在**（首次运行新版）：
    1.  遍历 `CalendarEvents`，找到当天的时间块，填入 `scheduledEventIds`。
    2.  遍历 `ChecklistTasks`，找到 `dueDate` 为当天的，填入 `todoTaskIds`。
    3.  保存 `DailyPlan`。
*   **如果存在**：直接读取。

### 第四阶段：UI 重构 (UI Refactoring)
1.  **改造 `DayView` / `WeekView`**：
    *   不再分别监听 `TaskListProvider` 和 `ScheduleProvider` 来做复杂的 `where` 过滤。
    *   改为监听 `DailyPlanProvider`，直接获取当天的三个 ID 列表。
    *   根据 ID 列表去查找实体对象进行渲染。
2.  **改造 `ScheduleMonitor`**：
    *   任务清理逻辑变得更简单：只需操作 `DailyPlan.todoTaskIds`，将其移除或移到明天。

---

## 3. 方案总结

*   **查询效率**：$O(1)$。直接获取当天 ID 列表，无需遍历全库。
*   **维护性**：所有“某天有什么安排”的逻辑全部收敛在 `DailyPlan` 中，不再散落在 UI 的 `build` 方法里。
*   **扩展性**：未来如果想做“将待办拖拽到时间轴”，只需在 `DailyPlan` 内部将 ID 从 `todoTaskIds` 移动到 `scheduledEventIds`（并创建对应的 Event 实体）。

准备好后，我们可以开始**第一阶段：创建 DailyPlanHive 模型**。
