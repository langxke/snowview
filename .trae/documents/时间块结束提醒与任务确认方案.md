# 时间块结束提醒与任务确认方案

根据您的需求，在时间块结束时询问用户“任务是否完成”是一个非常好的交互闭环，既起到了提醒作用，又自然地处理了任务状态。

目前系统**缺乏一个全局的后台监控机制**来实时检测“时间块结束”这一事件。现有的 `FocusScreen` 只有在界面打开时才会检查，而后台（最小化时）没有任何逻辑在运行。

## 推荐方案：前台检测 + 桌面通知 + 弹窗确认

鉴于 SnowView 是一个桌面端应用（Windows/Linux），我们采用 **“被动检测 + 主动交互”** 的方式来实现：

### 1. 核心机制设计
*   **监控时机**：利用应用内现有的 `ScheduleProvider` 或新建一个全局 `ScheduleMonitor`。
*   **触发条件**：
    1.  每分钟检查一次当前时间。
    2.  检测是否有正在进行的时间块 `end_time` 刚刚过去（例如 `now >= end && now < end + 1min`）。
    3.  或者维护一个 `NextEventEndTime` 指针，倒计时结束后触发。

### 2. 交互流程
当系统检测到某个时间块（关联了 Task）结束时：

1.  **第一步：系统通知 (Notification)**
    *   **标题**：时间块结束提醒
    *   **内容**：`"您安排的【开发SnowView】时段已结束。"`
    *   **作用**：即使用户在看浏览器或其他软件，也能收到 Windows 系统右下角的弹窗提醒。

2.  **第二步：应用内弹窗 (Dialog)**
    *   当用户点击通知回到软件，或软件处于前台时，弹出一个模态对话框。
    *   **询问**：`"计划时间已到，任务【开发SnowView】是否已完成？"`
    *   **选项 A：已完成 (Done)** -> 自动将该 Task 标记为 Completed，并在清单中归档。
    *   **选项 B：未完成 (Not Yet)** -> 什么都不做（任务保留在清单中，等待下次分配或手动处理），**或者**提供“延长 15 分钟”的快捷选项。
    *   **选项 C：忽略** -> 关闭弹窗。

### 3. 技术可行性与局限
*   **前台运行**：如果 SnowView 处于打开状态（哪怕最小化），Timer 可以正常运行，能准确触发。
*   **完全退出**：如果用户彻底关闭了软件，则无法提醒（这是桌面应用的常规行为）。
*   **通知支持**：目前的 `NotificationService` 需要确保存支持 Windows 平台（之前分析显示桌面端通知可能被注释或仅打印日志，需要修复）。

## 实施建议

我建议分两步走：

1.  **修复/启用桌面通知**：确保 `flutter_local_notifications` 在 Windows 上能正常弹出系统消息。
2.  **实现全局监控器**：在 `MainLayout` 或 `App` 层级挂载一个监听器，实时比对当前日程，触发上述交互。
