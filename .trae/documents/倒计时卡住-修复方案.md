## 原因判断

* 当前倒计时 UI 依赖 `ScheduleMonitorContentState._overlayTickTimer` 每秒调用 `OverlayEntry.markNeedsBuild()` 才会刷新。

* 你看到卡在 “自动关闭 09:59” 说明：Overlay 首次更新过一次，但后续 `markNeedsBuild()` 没有再驱动 OverlayEntry 重新 build（在 Windows 上这个方式不够稳，或被某次状态变化/异常打断后不再触发）。

## 修复目标

* 倒计时与进度条必须稳定每秒更新。

* 10 分钟到点自动关闭，并按“未完成”处理（清除询问态、必要时重置 task dueDate）。

* 不新增任何持久化字段，仍以“弹窗存在=未知态”。

## 实施方案（把倒计时刷新逻辑放进 Overlay 自身）

### 1) 用 StreamBuilder 驱动倒计时刷新（替代 markNeedsBuild）

* 在 `_createOverlayEntry` 的倒计时区域，改成：

  * `StreamBuilder<int>(stream: Stream.periodic(const Duration(seconds: 1), (i) => i), ...)`

  * 每次 build 内用 `DateTime.now() - showTime` 计算剩余 `mm:ss` 与进度条 `value`。

* 这样倒计时的刷新完全由 widget 子树自己触发，不依赖 `OverlayEntry.markNeedsBuild()`。

### 2) 在倒计时归零时触发一次“超时关闭”

* 在 `ScheduleMonitorContentState` 增加 `Set<String> _timeoutHandledKeys` 防止多次触发。

* 在 StreamBuilder 每次刷新时：

  * 如果 `remaining <= 0` 且未处理过：标记已处理并异步调用 `_handleOverlayTimeout(overlayKey, taskId, taskProvider)`

* `_handleOverlayTimeout` 做三件事：

  * `_removeOverlay(overlayKey)`（会清除询问态）

  * 从 `_pendingDialogs` 移除

  * 若 `taskId != null`，执行 `_resetIncompleteTask`（等价于“下次再做”）

### 3) 清理无用的每秒 tick（可选但推荐）

* 删除 `_overlayTickTimer` 与 `_tickOverlays()`，避免额外定时器。

* 保留 `_monitorTimer`（30 秒检测结束）即可；超时由 Overlay 自己处理。

## 验证点

1. 点“立即结束”弹出右下角确认框后，`09:59 -> 09:58 -> ...` 连续递减，进度条同步缩短。
2. 关闭/下次再做/已完成：弹窗消失，时间块退出未知态。
3. 等待 10 分钟：弹窗自动消失，时间块按未完成显示（结束在过去则按过期未完成样式）。
