# AI 对话性能优化快速指南

## 🎯 问题识别

### 症状
- ✅ 流式输出时整个界面卡顿
- ✅ 低端设备明显掉帧
- ✅ 输入框、按钮暂时无响应
- ✅ 滚动消息列表有延迟

### 根本原因
```
每个 chunk (50-100ms) → notifyListeners()
    ↓
整个 Consumer<AIProvider> 重建
    ↓
所有子组件重建（Header、TabBar、ListView、InputArea）
    ↓
性能瓶颈！
```

---

## ✅ 解决方案

### 核心思想
**局部更新** = `Selector`（精细化监听）+ `StreamBuilder`（流式隔离）

### 三步实施

#### 1️⃣ AISession 添加 Stream 支持
```dart
class AISession {
  StreamController<String>? _contentStreamController;
  String? _currentStreamingMessageId;
  
  Stream<String>? get currentMessageStream => _contentStreamController?.stream;
  String? get currentStreamingMessageId => _currentStreamingMessageId;
  
  void _updateAssistantMessage(String messageId, String content) {
    messages[index] = ChatMessageHive.assistant(...);
    
    // 🎯 通过 Stream 发送，不调用 notifyChanged
    if (_currentStreamingMessageId == messageId) {
      _contentStreamController!.add(content);
    }
    // ❌ 不再调用 _notifyChanged()
  }
}
```

#### 2️⃣ AIProvider 暴露 Stream
```dart
class AIProvider {
  Stream<String>? get currentMessageStream {
    return _sessions[_currentSessionId]?.currentMessageStream;
  }
  
  String? get currentStreamingMessageId {
    return _sessions[_currentSessionId]?.currentStreamingMessageId;
  }
}
```

#### 3️⃣ UI 使用 Selector + StreamBuilder
```dart
@override
Widget build(BuildContext context) {
  return Column(
    children: [
      // 精细化监听，只在相关数据变化时重建
      Selector<AIProvider, int>(
        selector: (_, p) => p.sessions.length,
        builder: (_, __, ___) => _buildHeader(...),
      ),
      
      // 消息列表
      Expanded(
        child: Selector<AIProvider, List<ChatMessageHive>>(
          selector: (_, p) => p.messages,
          builder: (_, messages, __) => ListView.builder(
            itemCount: messages.length,
            itemBuilder: (_, index) {
              final message = messages[index];
              
              // 🎯 正在生成的消息用 StreamBuilder
              if (message.id == streamingMessageId) {
                return StreamBuilder<String>(
                  stream: provider.currentMessageStream,
                  builder: (_, snapshot) {
                    return ChatMessageBubble(
                      message: message.copyWith(content: snapshot.data),
                    );
                  },
                );
              }
              
              // 普通消息直接显示
              return ChatMessageBubble(message: message);
            },
          ),
        ),
      ),
    ],
  );
}
```

## 🔑 关键要点

### ✅ 做对的事
1. **Selector** 监听具体字段，不监听整个 Provider
2. **StreamBuilder** 隔离流式输出
3. **只更新变化的部分**

### ❌ 避免的坑
1. 不要用 `Consumer<AIProvider>` 包裹整个界面
2. 不要在流式输出时调用 `notifyListeners()`
3. 不要让不相关的组件重建

## 💡 原理解释

### 为什么这样优化有效？

**问题根源**：
```
_updateAssistantMessage() → _notifyChanged()
    ↓
onStateChanged?.call()
    ↓
AIProvider._safeNotifyListeners()
    ↓
notifyListeners()
    ↓
Consumer<AIProvider> 重建
    ↓
整个 Column 及所有子组件重建
```

**优化原理**：
```
_updateAssistantMessage() → _contentStreamController.add()
    ↓
Stream 发送数据
    ↓
只有 StreamBuilder 收到通知
    ↓
只重建那一条消息的 ChatMessageBubble
    ↓
其他组件完全不受影响！
```

### Flutter 的响应式特性

- `Selector`：精细化 `shouldRebuild` 逻辑
- `StreamBuilder`：独立的数据流订阅
- 两者结合：**完美的局部更新**
