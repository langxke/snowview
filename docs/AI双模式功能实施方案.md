## 1. 功能概述

### 1.1 需求背景

当前AI助手收到用户需求时会立即执行操作，但在规划、讨论类场景中，用户希望AI先提供方案供确认后再执行。

### 1.2 解决方案

引入**思考模式**和**行动模式**：
- **🧠 思考模式**：AI提供规划和建议，不执行具体操作
- **⚡ 行动模式**：AI主动调用工具执行操作（当前默认行为）

### 1.3 使用场景

| 模式 | 适用场景 | 示例 |
|------|---------|------|
| 🧠 思考 | 规划、讨论、咨询 | "帮我规划学习路线" |
| ⚡ 行动 | 执行、操作、创建 | "帮我创建一个任务" |

## 2. UI设计

### 2.1 布局结构

```
┌─────────────────────────────────────────────┐
│  🤖 AI助手                   [新建] [×]      │ ← 标题栏（不变）
├─────────────────────────────────────────────┤
│  ◀ [对话1] [对话2*] [+] ▶                   │ ← 对话标签栏
├─────────────────────────────────────────────┤
│                                             │
│  消息列表区域...                             │
│                                             │
├─────────────────────────────────────────────┤
│ [▼ 🧠 思考模式]              [发送] 🟢      │ ← 底部：下拉选择器+发送按钮
└─────────────────────────────────────────────┘
```

**说明**：
- 模式选择器位于输入框**左下角**
- 使用**下拉菜单**（DropdownButton）而非分段按钮
- 发送按钮颜色随模式变化：
  - 🟢 **思考模式**：绿色（`Colors.green`）
  - 🟣 **行动模式**：蓝紫色（当前主题色）

### 2.2 下拉选择器设计

**尺寸和样式**：
- 高度：36-40px（比输入框略矮）
- 字体大小：12-13px（小号字体）
- 图标大小：16px
- 最小宽度：120px

**下拉选项**：
```
┌──────────────────────┐
│ 🧠 思考模式          │ ← 绿色主题
│ ⚡ 行动模式          │ ← 蓝紫色主题
└──────────────────────┘
```

**选中状态**：
- 思考模式：下拉框显示绿色边框/背景色调
- 行动模式：下拉框显示蓝紫色边框/背景色调

### 2.3 发送按钮颜色规则

| 模式 | 按钮颜色 | 色值示例 |
|------|---------|---------|
| 🧠 思考 | 绿色 | `Colors.green[600]` |
| ⚡ 行动 | 蓝紫色 | `colorScheme.primary` |

**视觉效果**：
- 发送按钮颜色变化提供**强烈的模式提示**
- 用户输入时始终能看到当前模式
- 颜色变化即时响应，无延迟

### 2.4 交互说明

1. **选择模式**：
   - 点击下拉框展开选项
   - 点击某个选项立即切换模式
   - 下拉框颜色立即变化
   - 发送按钮颜色同步变化

2. **视觉反馈**：
   - 下拉框有微妙的颜色提示（边框或浅色背景）
   - 发送按钮提供明显的颜色对比
   - 悬停时显示 Tooltip："思考模式：AI将提供方案"

3. **布局调整**：
   - 输入框与下拉框、发送按钮在同一行
   - 合理的间距（8-12px）
   - 确保三个元素垂直居中对齐

### 步骤2：AI上下文构建器改造

**目标**：根据不同模式生成不同的行为准则

**涉及文件**：
- `lib/services/ai_context_builder.dart`

**任务清单**：
- [ ] 修改 `build()` 方法，添加 `mode` 参数（默认 `'action'`）
- [ ] 添加 `_getModeName(mode)` 方法：返回模式显示名称
- [ ] 添加 `_getModeRules(mode)` 方法：根据模式返回不同规则
- [ ] 添加 `_getThinkingModeRules()` 方法：定义思考模式行为准则
- [ ] 添加 `_getActionModeRules()` 方法：定义行动模式行为准则

**核心规则差异**：

| 方面 | 思考模式 | 行动模式 |
|------|---------|---------|
| 工具调用 | 只能用查询类工具 | 可用所有工具 |
| 响应方式 | 提供方案+引导确认 | 直接执行+简洁反馈 |
| 输出格式 | 结构化方案 | 操作结果 |

**思考模式核心规则**：
```
1. 只提供方案，不执行操作
   - 不要调用 create_*, update_*, delete_* 类工具
   - 可以调用 query_*, get_*, find_* 类查询工具

2. 提供结构化方案
   - 清晰的步骤和时间安排
   - 具体的任务或行动项
   - 预期效果和注意事项

3. 引导用户确认
   - "确认后我可以帮你执行"
   - "如需修改请告诉我"
   - "你也可以切换到行动模式让我执行"
```

**行动模式核心规则**：
```
1. 主动执行，不只是建议
   - 直接调用工具完成操作
   - 不要问"需要我帮你创建吗"

2. 快速简洁反馈
   - 重点说明完成了什么
   - 避免冗长解释

3. 支持多步操作
   - 连续调用工具完成整个流程
```

    height: 36,
    padding: EdgeInsets.symmetric(horizontal: 12),
    decoration: BoxDecoration(
      border: Border.all(color: _getModeColor(aiProvider.currentMode).withOpacity(0.5)),
      borderRadius: BorderRadius.circular(8),
    ),
    child: DropdownButton<String>(
      value: aiProvider.currentMode,
      underline: SizedBox(), // 去除默认下划线
      icon: Icon(Icons.arrow_drop_down, size: 20),
      style: TextStyle(fontSize: 12),
      items: [
        DropdownMenuItem(
          value: 'thinking',
          child: Row(
            children: [
              Icon(Icons.psychology, size: 16, color: Colors.green),
              SizedBox(width: 6),
              Text('思考模式', style: TextStyle(fontSize: 12)),
            ],
          ),
        ),
        DropdownMenuItem(
          value: 'action',
          child: Row(
            children: [
              Icon(Icons.bolt, size: 16, color: colorScheme.primary),
              SizedBox(width: 6),
              Text('行动模式', style: TextStyle(fontSize: 12)),

      ],
      onChanged: (newMode) {
        if (newMode != null) {
          aiProvider.setMode(newMode);
        }
      },
    ),
  );
}

## 4. 技术细节

### 4.1 核心思路

通过**提示词工程**控制AI行为：
- 思考模式：提示词明确"不要调用创建/更新/删除类工具"
- 行动模式：提示词强调"主动执行操作"

### 4.2 数据流

```
用户点击切换按钮
    ↓
AIProvider.setMode(newMode)
    ↓
更新 _currentMode 状态
    ↓
保存到 AIConfigHive
    ↓
notifyListeners()
    ↓
UI更新按钮状态
    ↓
用户发送消息
    ↓
AIProvider.sendMessage()
    ↓
AIContextBuilder.build(mode: _currentMode)
    ↓
生成包含模式规则的系统提示词
    ↓
发送到AI API
    ↓
AI根据规则响应
```

### 4.3 关键设计点

1. **默认行动模式**：保持当前用户习惯，新用户开箱即用
2. **全局模式管理**：所有对话共享同一模式设置，简化实现
3. **持久化存储**：重启后恢复上次模式，提升用户体验
4. **提示词驱动**：通过提示词约束AI行为，无需修改工具定义
5. **向下兼容**：旧数据自动使用默认值，不影响现有功能

### 4.4 Hive字段分配

- `AIConfigHive.aiMode`: HiveField(7)
- 确保该字段编号未被占用
- 使用 `String` 类型存储模式值

## 5. 可选增强（后续迭代）

### 5.1 每会话独立模式
**功能**：每个对话会话记住自己的模式偏好  
**实现**：在 `ChatSessionHive` 中添加 `preferredMode` 字段  
**价值**：不同主题的对话可以使用不同模式

### 5.2 输入框内嵌提示
**功能**：在输入框 placeholder 中显示当前模式  
**示例**：
- 思考模式：`请输入问题，AI将为您规划方案...`
- 行动模式：`请输入指令，AI将立即执行...`  
**价值**：用户始终清楚当前AI的行为模式

### 5.3 智能模式推荐
**功能**：根据用户输入内容，AI建议切换到合适的模式  
**示例**：检测到"规划"、"如何"等关键词，建议切换到思考模式  
**价值**：降低用户学习成本

### 5.4 模式快捷键
**功能**：键盘快捷键快速切换模式  
**配置**：`Ctrl+T` 思考模式，`Ctrl+A` 行动模式  
**价值**：提高高频用户的操作效率

### 5.5 模式历史统计
**功能**：统计用户使用各模式的频率  
**价值**：了解用户习惯，优化默认设置

## 6. 风险与注意事项

### 6.1 AI理解偏差
**风险**：AI可能不完全遵守提示词约束，在思考模式下仍调用工具  
**影响**：用户体验不符合预期  
**缓解措施**：
- 在提示词中多次强调禁止行为
- 使用明确的示例和格式要求
- 如必要，可在工具执行层添加模式检查

### 6.2 用户学习成本
**风险**：用户可能不理解两种模式的区别，造成困惑  
**影响**：降低功能使用率  
**缓解措施**：
- 首次使用时显示引导提示
- 在设置中添加功能说明
- 按钮使用直观的图标和文字

### 6.3 数据迁移
**风险**：旧用户数据没有 `aiMode` 字段，可能引发错误  
**影响**：应用崩溃或功能异常  
**缓解措施**：
- 使用默认值 `'action'` 确保兼容
- Hive自动处理缺失字段

### 6.4 模式误操作
**风险**：用户忘记切换模式，导致操作结果不符合预期  
**影响**：用户挫败感  
**缓解措施**：
- 模式按钮位置显眼
- 考虑添加模式指示器
- AI在响应中可提醒当前模式
