# 雪象 (SnowView) 项目需求文档

## 1. 项目概述

### 1.1 项目基本信息
- **项目名称**：雪象 (SnowView)
- **项目类型**：桌面端应用程序
- **开发平台**：Flutter
- **目标平台**：Windows、macOS、Linux
- **开发模式**：个人项目
- **架构模式**：单体应用架构

### 1.2 项目定位
雪象是一款基于AI辅助的智能日程规划和专注工具，旨在帮助用户高效管理学习任务、提升专注力，通过智能算法优化时间分配，实现个人目标的高效达成。

### 1.3 目标用户
- **主要用户**：学生、职场人士、自由职业者
- **使用场景**：学习新技能、项目管理、个人效率提升
- **用户特征**：注重效率、有明确学习目标、需要时间管理工具

## 2. 核心功能需求

### 2.1 AI任务生成模块
- **功能描述**：基于用户输入的学习目标，自动生成具体的任务列表
- **输入方式**：文本输入、语音输入（后期扩展）
- **AI服务**：OpenAI GPT-3.5/4.0 API
- **输出内容**：
  - 任务标题和详细描述
  - 任务优先级分类
  - 预估完成时间
  - 任务依赖关系
  - 学习资源推荐

### 2.2 智能日程规划模块
- **功能描述**：将生成的任务智能分配到用户的时间表中
- **规划算法**：
  - 基于用户时间偏好（工作日/周末、工作时间段）
  - 任务优先级排序
  - 任务依赖关系考虑
  - 用户专注力曲线优化
- **时间管理**：
  - 支持自定义工作时间
  - 休息时间自动安排
  - 任务缓冲时间预留
- **动态调整**：
  - 任务延期自动重排
  - 临时任务插入处理
  - 计划变更智能提醒

### 2.3 专注工具模块
- **番茄钟功能**：
  - 标准25分钟工作+5分钟休息
  - 自定义时间设置
  - 长休息时间（每4个番茄钟后15-30分钟）
  - 专注模式（屏蔽干扰）
- **专注时间记录**：
  - 每日专注时间统计
  - 任务专注时长记录
  - 专注效率分析
- **环境音效**：
  - 白噪音播放
  - 自然声音（雨声、海浪等）
  - 背景音乐集成

### 2.4 任务管理模块
- **基础功能**：
  - 任务创建、编辑、删除
  - 任务状态跟踪（待办、进行中、已完成、已取消）
  - 任务分类标签
  - 任务搜索和筛选
- **高级功能**：
  - 任务模板保存
  - 任务复制和移动
  - 批量操作
  - 任务历史记录

### 2.5 任务-日历联动模块 ✨（已实现）
- **功能描述**：将清单任务与日历时间段关联，实现任务的时间规划和可视化
- **核心功能**：
  - 为任务创建工作会话（Work Session）
  - 关联到整个任务或特定子步骤
  - 在日历中显示任务名称和类别颜色
  - 统一时间块模型（TimeBlock）统一展示事件和任务
- **工作会话特性**：
  - 选择日期和时间段
  - 添加备注信息
  - 状态管理（planned/completed/cancelled）
  - 时间冲突检测
- **数据一致性**：
  - 删除任务时级联删除所有会话
  - 删除子步骤时会话关联到整个任务
  - 任务进度统计和可视化
- **用户界面**：
  - 任务详情面板的"时间规划"标签页
  - 工作会话列表（按状态分组）
  - 会话统计（计划时长、实际投入）
  - 进度条可视化

### 2.6 数据管理模块
- **本地存储**：
  - Hive NoSQL数据库存储
  - 数据自动序列化/反序列化
  - 自动备份机制
- **数据导出**：
  - JSON格式导出
  - CSV格式导出
  - 任务报告生成
- **数据同步**（预留扩展）：
  - 云端同步接口预留
  - 多设备数据同步
  - 数据冲突解决机制

### 4.2 项目结构详解

#### 4.2.1 整体架构说明
本项目采用**Clean Architecture（清洁架构）**设计模式，参考滴答清单、微软Todo等成熟产品的架构设计，将代码分为四个层次：

1. **表现层（Presentation Layer）**：负责UI展示和用户交互
2. **业务逻辑层（Domain Layer）**：包含核心业务规则和用例
3. **数据层（Data Layer）**：负责数据存储和外部API调用
4. **服务层（Services Layer）**：提供跨模块的通用服务

#### 4.2.3 架构层次说明

**1. 仓库接口（Repository Interface）**
- **作用**：定义数据操作的抽象接口，实现依赖倒置原则
- **示例**：`TaskRepositoryInterface`、`ScheduleRepositoryInterface`、`FocusRepositoryInterface` 分别定义任务、日程与专注数据的读写契约
- **好处**：业务逻辑层不依赖具体的数据实现，便于测试和切换数据源

**2. 用例（Use Case）**
- **作用**：封装具体的业务操作流程，每个用例代表一个完整的业务场景
- **示例**：`CreateTaskUseCase` 包含创建任务的完整流程；`StartFocusSessionUseCase` 依赖 `FocusRepositoryInterface` 管理专注会话；`GenerateScheduleUseCase` 产生日程集合
- **好处**：业务逻辑清晰，易于测试和维护

**3. 服务层（Services Layer）**
- **作用**：提供跨模块的通用服务，处理复杂的业务逻辑
- **示例**：`ScheduleService` 包含日程规划的复杂算法，`AIService` 封装OpenAI API调用
- **好处**：复用性强，便于统一管理和优化

### 4.3 数据存储设计详解

#### 4.3.1 数据存储设计原则
参考滴答清单、微软Todo等成熟产品的数据模型设计，采用Hive NoSQL数据库设计，支持：
- **任务层次化**：支持主任务和子任务关联
- **时间管理**：精确的时间记录和统计
- **标签系统**：灵活的任务分类和标签
- **专注统计**：详细的效率分析数据

#### 4.3.2 Hive数据模型详细说明（实际实现）

```dart
// Hive Box集合设计（实际使用）
// Box: calendar_events    - 日历事件
// Box: work_sessions      - 工作会话
// Box: task_categories    - 任务类别
// Box: checklist_tasks    - 清单任务

// ===== 核心数据模型（已实现） =====

// 日历事件模型（存储独立的日历事件）
@HiveType(typeId: 0)
class CalendarEventHive extends HiveObject {
  @HiveField(0)
  String id;                               // 唯一标识符
  
  @HiveField(1)
  String title;                            // 活动标题
  
  @HiveField(2)
  String description;                      // 活动描述
  
  @HiveField(3)
  bool allDay;                             // 是否全天活动
  
  @HiveField(4)
  DateTime start;                          // 开始时间
  
  @HiveField(5)
  DateTime end;                            // 结束时间
  
  @HiveField(6)
  int colorValue;                          // 颜色值 (Color.value)
  
  // 计算属性
  Color get color => Color(colorValue);
  set color(Color color) => colorValue = color.value;
  
  // 工具方法
  bool intersects(DateTime day) { /* 检查是否与指定日期相交 */ }
  CalendarEventHive copyWith({...}) { /* 创建副本 */ }
}

// 任务类别模型（类似滴答清单的分组）
@HiveType(typeId: 1)
class TaskCategoryHive extends HiveObject {
  @HiveField(0)
  String id;                               // 唯一标识
  
  @HiveField(1)
  String name;                             // 类别名称（如：工作、学习、生活）
  
  @HiveField(2)
  int colorValue;                          // 主题色值
  
  @HiveField(3)
  int order;                               // 排序序号
  
  @HiveField(4)
  DateTime createdAt;                      // 创建时间
  
  // 计算属性
  Color get color => Color(colorValue);
  set color(Color color) => colorValue = color.value;
}
```

#### 4.3.3 Hive数据存储设计特点（实际实现）

**1. 实际采用的设计模式**
- **清单任务模式**：参考滴答清单，使用 `ChecklistTaskHive` + `SubTaskHive` + `TaskCategoryHive` 的组合设计
- **任务-日历分离**：日历事件 (`CalendarEventHive`) 和任务工作会话 (`WorkSessionHive`) 分开存储
- **统一时间块模型**：通过 `TimeBlock` 统一展示日历事件和任务会话

**2. TypeId分配表（已使用）**
| TypeId | 类名 | 说明 | 状态 |
|--------|------|------|------|
| 0 | CalendarEventHive | 日历事件 | ✅ 已实现 |
| 1 | TaskCategoryHive | 任务类别 | ✅ 已实现 |
| 2 | SubTaskHive | 子步骤 | ✅ 已实现 |
| 3 | ChecklistTaskHive | 清单任务 | ✅ 已实现 |
| 4 | WorkSessionHive | 工作会话 | ✅ 已实现 |
| 5+ | - | 预留给未来扩展 | - |

**3. Hive Box存储策略**
- **calendar_events** - 存储所有日历事件
- **work_sessions** - 存储任务的工作会话
- **task_categories** - 存储任务类别
- **checklist_tasks** - 存储清单任务

**4. 数据关联设计**
- **类别-任务关联**：通过 `categoryId` 关联任务和类别
- **任务-子步骤关联**：子步骤列表直接嵌入任务对象中
- **任务-工作会话关联**：通过 `taskId` 和可选的 `subTaskId` 关联
- **级联删除**：删除任务时自动删除所有关联的工作会话

**5. 核心功能支持**
- ✅ **清单任务管理**：完整的CRUD操作、类别管理、子步骤管理
- ✅ **日历事件管理**：独立的事件系统，支持全天事件
- ✅ **任务-日历联动**：工作会话关联任务，在日历中显示任务名称
- ⏳ **专注工具**：预留 `focusSessionId` 字段，待实现
- ⏳ **AI任务生成**：框架已预留，待集成

**6. 数据完整性保障**
- **唯一标识**：所有模型使用 UUID 确保唯一性
- **时间戳**：记录创建时间和完成时间
- **状态管理**：明确的状态字段（planned/completed/cancelled）
- **级联保护**：删除类别时检查是否有任务，删除任务时级联删除会话
- **哨兵值处理**：使用 `_undefined` 哨兵值正确处理可选字段的 null 清除

**7. 性能优化**
- **直接对象存储**：Hive直接存储Dart对象，无需序列化
- **懒加载**：按需加载任务和事件
- **索引优化**：通过日期和类别快速查询
- **内存缓存**：Provider层缓存常用数据
